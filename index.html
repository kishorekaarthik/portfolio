CyberShield

Machine learning and a browser extension, with a paper to prove it

A cyberbullying detection platform built to catch abuse before it gets posted, not after. It has two halves: a multimodal deep learning model for the research, and a fast, explainable detection engine that runs a live Flask API and a Chrome extension.

  • Multimodal fusion model. DistilBERT reads the text, ResNet-18 reads the image, and a small emoji embedding picks up the subtext a clown emoji carries. The three are fused, passed through an adapter and a transformer encoder layer, then split into a 6-class abuse classifier and an aggression score. The PyTorch training pipeline runs on MMHS150K, using a majority vote across annotator labels.
  • Explainable detection engine. Every flag comes with its reasons. Weighted lexicon and pattern rules cover personal attacks, threats, suicide encouragement, dehumanizing comparisons, sexual harassment, and stacked insults.
  • Anti-evasion. Normalizes l33tspeak, stretched-out letters, and s p a c e d words before scoring, so creative spelling doesn’t sneak through.
  • Risk zones. Scores fall into Safe, Uncertain, Moderate, or High, mapped to a non-enforcing policy layer: monitor, visibility filtering, or a warning.
  • Safe Compose extension. A Manifest V3 Chrome extension for X/Twitter that scores the post as you type, shows a live toxicity meter, highlights the trigger words, and offers “Rewrite with Empathy”, which swaps hostile phrases for civil ones and re-scores the result.
  • Account-level view. Scans a user’s recent posts through the X API and rolls them into one account risk score, plus a prototype “bully ring” dashboard that groups hostile posts by source account.

PyTorch, DistilBERT, ResNet-18, Flask, Chrome extension (MV3), X API

SecureDB Vault

Multi-tenant PII tokenization service, built for the DPDP Act 2023

A vault for the data nobody should be able to read: PAN, Aadhaar and bank account numbers go in through a REST API and come back out as tokens. Every company using it gets its own locked room, every access is written down in ink that can’t be erased, and the real values only come out when a policy says so.

  • Envelope encryption. Each tenant gets its own AES-256-GCM data key, wrapped by a master key that lives in the OS keychain. Every ciphertext is cryptographically bound to its tenant, token and key version, so a value copied into the wrong place simply won’t decrypt.
  • Tenant isolation in the database. Forced PostgreSQL row-level security plus a least-privilege application role with column-level grants. Even a bug in the API can’t read another tenant’s rows.
  • Tamper-evident audit log. A hash-chained log written in the same transaction as every operation, with a verification endpoint that pinpoints exactly which entry was edited, deleted or reordered. The audit table is append-only.
  • Deny-by-default access. Per-API-key policies decide allow, mask or deny for each field type, with scoped keys, rate limiting, and responses that never echo back what you sent.
  • DPDP rights and key rotation. Data-subject erasure and export, zero-downtime data-key rotation with resumable batched re-encryption, and crash-safe master-key rotation.
  • Tested like it matters. 410+ automated tests (unit, property-based, concurrency and security-regression) run against a real PostgreSQL instance, with strict type checking and linting.

Python, FastAPI, PostgreSQL, SQLAlchemy, AES-256-GCM, Argon2id
